3. q8_scale standalone (results/q8scale-generic.ys, q8scale-ecp5.ys)
-------------------------------------------------------------------
**NEW real measurement -- EXP-FPGA-DIV-001 attempted this and had to
kill it mid-`autoname` after "several minutes," only ever recording an
extrapolated ~75-80K-cell ESTIMATE.** This session completed both the
generic and ECP5-mapped run to completion.

Generic: 21,800 total cells (roughly 2.13x the standalone divider's own
10,234, consistent with "2 divider instances + a small amount of glue
logic," `q8_scale.sv`'s own header comment). CPU 140.92s user / 11.62s
system, MEM 1873.46 MB (yosys) / 1,918,424 KB peak RSS, wall 2:36.

ECP5-mapped: **123,742 total cells** (LUT4=62,940, CCU2C=20,542,
PFUMX=25,907, L6MUX21=14,288, TRELLIS_FF=65, 0 hard multipliers). CPU
519.95s user / 38.83s system, MEM 2619.97 MB (yosys) / 2,682,848 KB
peak RSS, wall 10:18. 0 problems (`check` pass).

**This corrects EXP-FPGA-DIV-001's own extrapolation, which turns out
to have been an UNDERESTIMATE, not an overestimate**: the real number
(123,742) is ~1.68x the standalone divider's own 73,629 ECP5 cells --
meaningfully less than a naive 2x-instance assumption (147,258) would
predict (yosys's technology mapper shares some cost between the two
parallel divider instances, the same qualitative effect
EXP-FPGA-DIV-001's own Phase B1 already documented for `q4_scale`'s
two-instance baseline), but well above the ~75-80K figure that had
only ever been a guess, never measured. Disclosed as a correction, not
glossed over.
