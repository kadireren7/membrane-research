# Phase 7.2: Academic Paper

Baseline: commit `ad6cf5f` (Phase 7.1, "docs: prepare MEMBRANE research
release"). Phase 7.1 packaged the already-verified Phase 0-6.5 research
as a reproducible release (README, reproduction guide, results summary,
release tooling). Phase 7.2's job: turn that same, already-measured work
into a submission-track academic manuscript — literature-grounded,
claim-audited, and figure/table-reproducible. **No new experiments were
run in this phase**; every number in `paper/main.md`/`paper/main.tex` was
already measured in a prior phase and is re-verified here, not
re-derived.

## Literature areas reviewed

15 topic areas were searched (WebSearch + WebFetch against primary
sources only — arXiv abstract pages, ACM DOIs, the CXL Consortium's own
site): KV-cache quantization, mixed-precision KV cache, KV-cache
eviction, sparse attention, attention sinks, heavy-hitter KV selection,
paged KV-cache management, KV-cache offloading, CPU/GPU/NVMe/CXL memory
tiering, near-memory processing, CXL memory expanders, FPGA-based
quantization, LLM inference memory systems, long-context inference, and
retrieval-aware attention systems.

**14 sources were used**, each independently verified against its own
arXiv abstract page (title, full author order, submission year, venue)
before being added to `paper/references.bib` — not taken from a
secondary summary. See `paper/related-work-matrix.md` for the full
12-column comparison and `paper/references.bib` for exact metadata.
Sources found during search but not used (because a closer, better-fit
source existed, or because their metadata could not be independently
confirmed) were simply not added — no placeholder or "et al., n.d."
entries were created.

## Final contribution wording

Five contributions (`paper/main.md` Introduction), each cross-checked
against `paper/related-work-matrix.md` before being finalized:

1. Runtime-calibrated hot/warm/cold KV-cache tiering over FP16/Q8/Q4,
   bit-exact vs. ggml across 100,000+ blocks.
2. Synthesizable FPGA datapath sharing the identical bit-exact
   arithmetic as the CPU reference, cosimulated across 520,000
   transactions — the **only** hedged "to our knowledge" claim in the
   list, since no absolute priority claim can be made from a search that
   was thorough but not exhaustive.
3. A disclosed, quantified negative result on PCIe-round-trip FPGA
   offload economics at live-decode batch sizes.
4. An exact (non-approximate) sparse KV retrieval architecture,
   distinguished from eviction-based and selection-based prior art.
5. A real out-of-core simulation and artifact-verification
   infrastructure that completed the 462/462-scenario unified sweep with
   every headline number automatically checked against its source.

"First"/"novel"/"unprecedented" are used nowhere in this list without an
explicit hedge, and `paper/scripts/verify-paper.py` checks this
automatically on every future edit (not just at the time of writing).

## Claim audit result

`paper/claim-audit.md` covers all 11 claims the task explicitly named
(128K×512, 462/462, 187x-321x traffic reduction, 360M-specific figures,
520,000 RTL transactions, quant parity vector counts, FPGA pipeline
sensitivity, 10ms bound failure, CPU compute floor, approximate-eviction
recall failure, micro-batching null result), each with exact wording,
claim type, source artifact, manifest entry, experiment configuration,
limitations, allowed wording, and prohibited overclaim wording.

**A real inconsistency was found and fixed while auditing.** The
original `paper/main.md` draft's RQ7/hardware-sensitivity discussion
initially risked implying the pipeline-count sensitivity result
generalized to SmolLM2-360M; the audit process confirmed (via
`benchmarks/cxl-sim/unified-sweep-hardware-sensitivity.csv`) that this
sub-sweep is SmolLM2-135M-only by original design, and the manuscript
was written to state that limitation explicitly in every place the
25.7x figure appears (claim C-07).

## Submission-readiness gaps (not submission-ready as-is)

Per `paper/submission-options.md`'s honest, per-venue analysis:

- **Systems venues (OSDI/SOSP/EuroSys)**: not ready — no real
  serving-stack integration, no 7B+-scale evaluation.
- **Architecture venues (ISCA/MICRO/HPCA/ASPLOS)**: partially ready —
  the negative PCIe-offload and pipeline-sensitivity results fit well,
  but real FPGA board results (Fmax/power/area) are missing.
- **ML systems venues (MLSys/NeurIPS/ICML systems tracks)**: partially
  ready — bit-exact quantization verification is a real contribution,
  but model scale (135M/360M) and prompt diversity are both below this
  literature's typical bar.
- **FPGA/reconfigurable computing venues (FCCM/FPL/FPGA)**: not ready —
  cosimulation + synthesizability checking is not this community's
  typical evidence bar; real place-and-route results are expected.
- **Workshop/demo tracks**: **closest to ready** — the manuscript's
  disclosure discipline, negative-results section, and artifact-
  verification infrastructure already meet what these tracks typically
  look for; remaining gaps are mostly formatting (venue-specific
  template, page limit), not substantive research gaps.

No specific venue or acceptance likelihood is claimed anywhere in this
project. `paper/main.tex` deliberately does not copy any specific
conference's LaTeX template, since none has been chosen and this
project has not confirmed any single template's license/access terms.

throughput," "real CXL acceleration," "production," "production-ready."
None of these appear unhedged anywhere in `paper/main.md` or
`paper/main.tex` as of this phase — verified automatically, not just by
manual review.
